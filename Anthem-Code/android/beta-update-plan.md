# แผนอัปเดตช่วง Closed Testing (Samecor App · com.samecor.app)

เริ่มทดสอบ: 2026-10-30 (รุ่น 2 / 1.0.1 เผยแพร่ใน Alpha) · provider ทดสอบ 16 วัน · ต้องมีผู้ทดสอบ ≥12 คนต่อเนื่อง ≥14 วัน
provider แนะนำให้อัปเดตแอป 2–3 ครั้ง และแจ้งเลขรุ่น + สิ่งที่แก้ทุกครั้ง

## หลักคิด
- แอปเป็น WebView ที่โหลด samecor.com: งานฝั่งเว็บ deploy แล้วผู้ทดสอบเห็นทันที ไม่ต้องอัปโหลดรุ่นใหม่ แต่ควรแจ้ง provider ด้วยว่า "อัปเดตฝั่งเว็บ"
- ปล่อยรุ่น Android ใหม่เฉพาะเมื่อมีงาน native จริง (ไม่ปล่อยรุ่นเปล่า)
- ทุกรุ่น: versionCode +1 ใน `capacitor-shell/android/app/build.gradle`

## รุ่นที่วางแผน
| รุ่น | ช่วง | งาน Android (ต้อง build ใหม่) | งานเว็บที่ปล่อยพร้อมกัน |
|---|---|---|---|
| 3 (1.0.2) | วันที่ 3–5 | ดาวน์โหลดไฟล์ใน WebView (QR PNG/SVG, เอกสาร), ปุ่มแชร์ใช้ share ของระบบ, สะพาน getAppVersion (หน้าตั้งค่าแสดง "เวอร์ชันแอป" — แอปรุ่น 2 ยังไม่แสดง) | ปุ่มฟีดแบ็ก beta บนมือถือ, ไม่แสดง hero ให้คนที่ล็อกอิน |
| 4 (1.0.3) | วันที่ 8–10 | แก้ตามฟีดแบ็กผู้ทดสอบ (ปุ่มย้อนกลับ, ลิงก์ภายนอก, การเปิดแอปครั้งแรก) | แก้บั๊กจากรายงานฟีดแบ็ก |
| 5 (1.0.4) | วันที่ 12–13 | ขัดเกลาก่อนสมัคร production (ความเสถียร, ไอคอน/สแปลช) | ข้อความ Store + ภาพหน้าจอใหม่ |

ปรับตามฟีดแบ็กจริงได้ ถ้าไม่มีงาน native ในช่วงนั้นให้ข้ามรุ่น

## ขั้นตอนต่อรุ่น
1. รวมงาน + merge เข้า main + deploy เว็บ (ถ้ามี)
2. versionCode / versionName ใหม่ → build signed `.aab` ตาม `capacitor-shell/README.md`
3. Play Console → Alpha → สร้างรุ่นใหม่ → อัปโหลด `.aab` → ใส่บันทึกประจำรุ่น → ส่งตรวจ
4. ติดตั้งจากลิงก์ทดสอบบนมือถือจริง ลองล็อกอิน tester@samecor.com
5. แจ้ง provider ตามแม่แบบด้านล่าง + จดในบันทึกการเปลี่ยนแปลง

## แม่แบบบันทึกประจำรุ่น (Play)
```
<th>

</th>
<en-US>
Fixes and improvements: (1–3 points)
</en-US>
```
