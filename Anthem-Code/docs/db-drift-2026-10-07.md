# Database drift — 7 Oct 2026

The app calls tables and functions that do not exist in the live database
(`zkflkpbmbozrchqncpzi`). Checked read-only against the live catalog and the last 24 h of API logs.

**Why it happened:** these objects are defined only in `Anthem-Code/supabase/migrations/` (the old
pre-unification folder, never applied to this project) or in loose `scripts/ecosystem/*.sql` files.
A few were in migrations recorded as applied but were later removed outside the migration system.
The canonical history is `Solo-Code/supabase/migrations/` — only files there reach production.

## Keep it from happening again

- Never run SQL by hand or via `scripts/apply-*.mjs` without the same file in `Solo-Code/supabase/migrations/`.
- Delete or archive `Anthem-Code/supabase/migrations/` so nobody assumes it is applied.
- After each schema change, regenerate types (`scripts/db-types/README.md`); a typecheck error on a
  table or RPC name means it is missing or misrouted.
