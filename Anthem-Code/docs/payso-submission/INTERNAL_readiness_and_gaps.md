## ยืนยันจากใบเสนอราคา Payso ตัวจริง (Q-202607000297, ตรวจ 9 ต.ค. 2569)
อ่านจากไฟล์ PDF ที่ผู้สมัครแนบ ไม่ใช่จากเอกสารภายใน:
- **ข้อ 5.2 บุคคลธรรมดา: ≤ 50,000 บาท/เดือน และ ≤ 20,000 บาท/รายการ** (ยืนยันตัวเลขเดิมแล้ว) · Payso สงวนสิทธิ์ปรับวงเงินตามประเภทธุรกิจ/ความเสี่ยง · ขอเพิ่มวงเงิน: LINE OA `@payso` หรือ 02-089-2869 กด 4 (แจ้งผลภายใน 1–2 วันทำการ)
- **ใบเสนอราคาหมดอายุ 31 ต.ค. 2569** — ต้องยืนยันและเดินเรื่องสัญญาก่อนวันนั้น ไม่เช่นนั้นอาจต้องขอใหม่
- ข้อ 4.1: เปิดระบบ Demo/Test ได้หลังยืนยันใบเสนอราคา · จะเปิดรับเงินจริง **ก่อนสัญญาสมบูรณ์** ต้องส่งเอกสารครบเพื่อ Pre-Approve (นี่คือรายการข้อ 4–15 ที่ Payso ขอ) · สัญญาเซ็นแบบออนไลน์หรือกระดาษ + รออนุมัติฝั่ง Payso ประมาณ 3–7 วันทำการ
- PromptPay: รับได้ 6–699,999 บาท/รายการ, 1.35% ขั้นต่ำ 5 บาท/รายการ, ยังไม่รวม VAT 7% · บัตร 3% (AMEX 4% เฉพาะ THB) · Internet/Mobile Banking 3% (ต่ำกว่า 1,000 บาท คิดเหมา 15 บาท)
- โอนเงินให้ร้านค้ารายสัปดาห์ T+7 (นับ 21:00 วันก่อน–20:59 วันนี้) · ค่าโอน 6 บาท (กสิกร) / 15 บาท (ธนาคารอื่น) ต่อรายการ · โอนอัตโนมัติขั้นต่ำ 100 บาท, สูงสุด 2,000,000 บาท/รอบ

### สิ่งที่ใบเสนอราคาไม่ได้ครอบคลุม (ต้องถาม Payso เป็นลายลักษณ์อักษร)
1. **การเป็น marketplace / พักเงินแทนบุคคลที่สาม** — ใบเสนอราคาเป็นแบบร้านค้าทั่วไป เงินโอนเข้าบัญชีของร้านค้าเอง ไม่มีข้อความเรื่องการจ่ายต่อให้ครีเอเตอร์
2. **ขั้นตอนคืนเงินของ PromptPay** — ข้อ 6 (Void / Refund / 14–30 วันทำการ / ค่าเพิ่ม 300 บาทเมื่อเกิน 7 วัน) เขียนไว้เฉพาะ **บัตรเครดิต/เดบิต** เราจะเริ่มด้วย PromptPay จึงยังไม่มีข้อกำหนดการคืนเงินที่ยืนยันได้ · หน้านโยบายของเราเขียนว่าคืน 7–14 วันทำการ ตัวเลขนี้ยังไม่มีแหล่งยืนยันสำหรับ PromptPay
3. กรณียกเลิกเกิน 7 วัน Payso คิด **300 บาท/รายการทุกกรณี** (บัตร) — นโยบายเราให้แพลตฟอร์มรับภาระในกรณีครีเอเตอร์ผิดเงื่อนไข ควรเช็กว่ากฎนี้ใช้กับ PromptPay ด้วยไหม

## ที่ยังขาดในระบบ (ไม่ควรอ้างกับ Payso ว่าใช้ได้)
- **หลังบ้านการเงิน** (`/admin/finance`): ฟังก์ชันฐานข้อมูลที่ใช้ตรวจ payout, ข้อพิพาท, ตั้งค่าธรรมเนียม ยังไม่มีบน DB (ดู `docs/db-drift-2026-10-07.md`) ต้องทำข้อ B ก่อนรับเงินจริง
- **AML** (`aml_flags`), **PDPA** (`privacy_requests`), **ลิขสิทธิ์** (`copyright_reports`): ตารางยังไม่มี หน้าหลังบ้านใช้ไม่ได้
- **บัตรเครดิตและโอนผ่านบัญชี**: ปุ่มในหน้าชำระเงินยังไม่เปิด (ขึ้นข้อความ “จะเปิดหลังยืนยัน tokenization” / “ยังไม่เปิดในรอบนี้”) ฝั่งเซิร์ฟเวอร์รับ token ได้แต่ฝั่งเบราว์เซอร์ยังไม่ tokenize — ตอนนี้ใช้ได้เฉพาะ PromptPay (เอกสารเขียนตามนี้) · หน้านโยบายคืนเงินยังเขียนว่ารองรับบัตร ซึ่งเป็น “ช่องทางที่เปิดใช้งานจริงจะแสดงตอนชำระ” จึงไม่ขัดแย้ง
- **ร้านสินค้า (Objects)**: อยู่ใน branch `wip/cursor-2026-10-09` ยังไม่ merge/ไม่ทดสอบ เอกสารระบุเป็น “กำลังพัฒนา”
- **ไม่มีเพดานราคาต่อรายการ 20,000 บาท** ในระบบ ถ้าจะอยู่ในวงเงินบุคคลธรรมดา ต้องจำกัดที่ใบเสนอราคา/ออเดอร์หรือแบ่งงวด
- **ยังไม่เคยมีธุรกรรมจริง** (`hire_orders` = 0): ควรผ่านการทดสอบ PromptPay โหมดทดสอบ 1 รอบเต็ม (จ่าย → ส่งงาน → อนุมัติ → ขอถอน) ก่อนยื่น

## เรื่องที่ควรถาม Payso ตรง ๆ (ตามเอกสารภายใน `docs/payments-payso.md`)
1. บุคคลธรรมดาเปิด **marketplace / พักเงินแทนบุคคลที่สาม** ได้หรือไม่ ต้องมีเงื่อนไขหรือใบอนุญาตเพิ่มไหม (ผมไม่ใช่ที่ปรึกษากฎหมาย — ควรขอคำตอบเป็นลายลักษณ์อักษร และปรึกษาผู้เชี่ยวชาญเรื่องการเป็นตัวกลางรับชำระเงิน)
2. วงเงิน 20,000 บาท/รายการ และ 50,000 บาท/เดือน ปรับได้เมื่อไหร่ และงานราคาสูงใช้ได้ไหมถ้าแบ่งงวด
3. การโอนให้ครีเอเตอร์ (payout) ทำเองจากบัญชีธนาคารหลังรับ settlement T+7 ได้หรือไม่ หรือต้องใช้บริการโอนของ Payso
4. การคืนเงิน/void ผ่าน API หรือทำใน Dashboard เท่านั้น (ระบบเรามีคำขอยกเลิกและคำนวณยอดคืนแล้ว แต่ยังไม่ได้เชื่อมการคืนเงินจริงกับ PSP)
5. คีย์/ SDK ของ Payso (โค้ดตอนนี้ยังเรียก Omise API)
