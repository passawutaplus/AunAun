## 2) ภาพรวมบทบาทเงิน

```
ผู้จ้าง (Buyer) ──จ่าย──► PaySo (PSP)
                              │
                              ▼
                     Aplus1 merchant account
                     (ถือเงิน + ledger ภายใน)
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
     Seller pending     Platform fee      Refund/Dispute
     (หลังส่งงาน+อนุมัติ)  (10% snapshot)   (ตามนโยบาย)
              │
              ▼
     Seller available → ถอนเข้าบัญชีธนาคารที่ verify แล้ว
     (หลัง PaySo settle T+7 + นโยบาย payout ของเรา)
```

**กฎสำคัญ**

1. Webhook “จ่ายสำเร็จ” → เครดิต seller เป็น **pending เท่านั้น** ยังไม่ใช่ available  
2. Available หลัง **ผู้จ้างกดอนุมัติงาน** (หรือ admin ปิด dispute) — ไม่ auto-approve จากเงียบ  
3. ตัวเลขเงินภายในเป็น **จำนวนเต็มสตางค์ (THB)**  
4. ค่าธรรมเนียมแพลตฟอร์ม **ถ่าย snapshot ตอนสร้างออเดอร์**  
5. **ห้าม** สัญญาว่าผู้ขายได้เงินเข้าบัญชีวันเดียว — ต้องคำนึง T+7 ของ PaySo

## 3) KYC / ยืนยันตัวตน (ก่อนรับเงินจ้าง / ถอน)

เส้นทางผู้ใช้: `/verify` · แอดมิน: `/admin/kyc`

### 3.1 ผู้ขาย (Freelancer / Creator) — ต้องผ่านก่อนเปิดรับจ้างเงินจริง / ถอน

| ขั้น | รายละเอียด |
|------|------------|
| 1 | สมัคร / ล็อกอิน · ยืนยันอีเมล (email/password) หรือ OAuth |
| 2 | กรอกโปรไฟล์พื้นฐาน · มีผลงานเผยแพร่ (แนะนำก่อนเปิด `allow_hire`) |
| 3 | เข้า `/verify` → อัปโหลด: **บัตรประชาชนไทย** + **selfie คู่บัตร** + **หน้าสมุดบัญชี** |
| 4 | ระบบช่วย: OCR อ่านบัตร (แก้ได้) · AI เช็กคุณภาพรูป/ selfie · checksum เลขบัตร · อายุ ≥ 18 · สัญชาติไทย · ที่อยู่ครบ · เบอร์ไทย |
| 5 | ยินยอม PDPA · attestation · ประกาศไม่ใช่ PEP / ไม่ติด sanctions |
| 6 | ส่งคำขอ → สถานะรอตรวจ (`shared.kyc_requests`) |
| 7 | แอดมินตรวจมือที่ `/admin/kyc` → อนุมัติ → `profiles.is_verified` + `kyc_expires_at` (re-KYC ทุก ~2 ปี) |
| 8 | ผูก **บัญชีธนาคารผู้รับเงิน** (ชื่อตรง KYC) — ต้อง verify ก่อนถอน |
| 9 | ถ้า KYC หมดอายุ → ห้าม payout / รับออเดอร์เงินใหม่จนกว่า re-KYC |

**ยังไม่มี (บอก PaySo ได้):** face-match อัตโนมัติเต็มรูป · screening list ภายนอกแบบ real-time — ตอนนี้แอดมินตรวจมือ (CDD light)

### 3.2 ผู้จ้าง (Buyer / Hirer)

| ขั้น | รายละเอียด |
|------|------------|
| 1 | สมัคร / ล็อกอิน · ยืนยันอีเมล |
| 2 | จ้างงานได้โดยยังไม่บังคับ KYC เต็ม (โฟกัส KYC ที่ฝั่งรับเงิน) |
| 3 | ตอน checkout ยอมรับนโยบายจ้างงาน + นโยบายชำระ/คืนเงิน (เก็บเวอร์ชัน consent) |
| 4 | ถ้าจ้างในนามบริษัท: เก็บ billing profile / เลขภาษีตามฟอร์ม (แยกจาก KYC ผู้ขาย) |

### 3.3 ฝั่งร้านค้า Aplus1 กับ PaySo (นิติบุคคล)

- KYC/เอกสารบริษัทกับ PaySo ตามที่คุณกำหนด (แยกจาก KYC ผู้ใช้บนแพลตฟอร์ม)  
- บัญชีรับเงิน settlement ของ Aplus1  
- อนุมัติรูปแบบถือเงินบุคคลที่สาม / marketplace ก่อนเปิด live charge

## 4) ลำดับจ้างงานครบวงจร (ต้นทาง → จ่าย → ส่งงาน → อนุมัติ → ถอน)

### Phase 0 — พร้อมจ้าง (ก่อนมีเงิน)

1. ผู้ขายตั้งโปรไฟล์ · ลงผลงาน · (ทางเลือก) เปิด Package บริการ  
2. ผู้ขายผ่าน **KYC** + ผูกบัญชีธนาคาร  
3. ผู้ขายเปิดรับจ้าง (`allow_hire` / สถานะโอกาส)  
4. ผู้จ้างค้นพบจาก **ผลงาน / โปรไฟล์ / Package**  
5. กดจ้าง / คุยต่อจากผลงาน → เปิดแชทมีบริบทผลงาน

### Phase 1 — ตกลงงาน (ยังไม่ตัดบัตร)

6. คุยในแชท (ขอบเขต · ราคา · กำหนดส่ง · มัดจำ%)  
7. ผู้ขายส่ง **ใบเสนอราคา / quote** (`hire_quotes`, หมดอายุ ~48 ชม.)  
8. ผู้จ้างยอมรับข้อเสนอ + ยอมรับนโยบาย  
9. ระบบสร้างออเดอร์รอชำระ · snapshot ค่าธรรมเนียมแพลตฟอร์ม + (ถ้ามี) อัตรา FX แสดงผล

### Phase 2 — ชำระเงินผ่าน PaySo

10. Checkout แสดง **ยอดจ่ายเป็นบาท** (+ ป้ายสกุลเงินแสดงผลถ้าเปิด)  
11. ช่องทาง: **PromptPay QR** (หลัก) และ/หรือ **บัตร** (มี surcharge ให้ผู้ซื้อเห็นก่อนยืนยัน ถ้าเปิด)  
12. ผู้จ้างจ่าย → PaySo charge  
13. **Webhook สำเร็จ** →  
    - อัปเดตสถานะออเดอร์ / hiring request เป็นตอบรับแล้ว  
    - Ledger: `payment_received` · ค่าธรรมเนียม PSP · **seller_pending_credit**  
    - **ยังไม่** `seller_available_credit`  
14. แจ้งเตือนทั้งสองฝ่าย · เอกสาร: ใบแจ้งหนี้/ใบเสร็จตามนโยบายเอกสารจ้าง

### Phase 3 — ทำงาน / ส่งมอบ

15. ผู้ขายเริ่มงาน · อัปเดตสถานะในแชท/แดชบอร์ด  
16. ผู้ขายส่งมอบ (`hire_deliveries`) → สถานะรออนุมัติ  
17. หน้าต่างโต้แย้ง (~7 วันถ้าเงียบ — นโยบายผลิตภัณฑ์: **อนุมัติเมื่อผู้จ้างกดเท่านั้น** ไม่ auto จากเงียบ เว้นแต่ตกลงใหม่)

### Phase 4 — อนุมัติ → เงินพร้อมถอน

18. ผู้จ้างกดอนุมัติงาน →  
    - pending → **available** ของผู้ขาย  
    - ตัด/บันทึก platform fee receipt (Aplus1 → ผู้ขาย)  
    - (ทางเลือก) หัก ณ ที่จ่าย 50 ทวิ — ไม่บล็อก payout ถ้ายังไม่ครบเอกสาร  
19. ผู้ขายรีวิว / ปิดงาน

### Phase 5 — ถอนเงินผู้ขาย (Payout)

20. ผู้ขายขอถอนเมื่อยอด available ≥ นโยบาย (ขั้นต่ำ **1,000 บาท**)  
21. ฟรี **1 ครั้ง/เดือนปฏิทิน** แล้วครั้งถัดไป **25 บาท**/ครั้ง  
22. รวมหลายออเดอร์เป็น batch โอน  
23. Aplus1 โอนจากยอดที่ **PaySo settle แล้ว (T+7)** ไปบัญชีที่ verify  
24. Ledger: `payout_reserved` → `payout_completed` / `payout_failed`  
25. แอดมินดูคิวที่ `/admin/finance`

### ทางแยก — ยกเลิก / คืนเงิน / ข้อพิพาท

| กรณี | พฤติกรรมที่ออกแบบ |
|------|-------------------|
| ยกเลิกก่อน/หลังจ่าย | ตาม `hire_cancel_requests` + นโยบายเงิน · งานที่ยกเลิก **ไม่เก็บ platform fee 10%** (ยกเว้นมีข้อยกเว้นชัด) |
| คืนมัดจำ / half_refund | คิดจาก **ยอดที่จ่ายแล้ว** ไม่ใช่ราคาเต็มงานที่ยังไม่จ่าย |
| Void วันเดียว (บัตร) | ตามกฎ PaySo · ไม่มีค่าธรรมเนียมเพิ่ม |
| Refund วันถัดไป+ | ผู้ซื้อได้เงินคืน ~14–30 วันทำการ · ค่าธรรมเนียม PSP อาจไม่คืน |
| ยกเลิกล่าช้า >7 วัน | ค่าปรับ **300 บาท**/รายการ (ใบเสนอ) — แบกเริ่มต้นที่แพลตฟอร์ม |
| Chargeback / dispute | แอดมิน hold → `dispute_hold` / `dispute_release` · ไม่ปล่อย available จนกว่าปิดเคส |
